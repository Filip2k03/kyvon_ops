## 1. Core Production Rule

From this point forward, **PRODUCTION** is the primary environment and sole release target. 

* **No Localhost in Production**: Localhost configurations exist only for sandboxed development inside the local source tree where technically unavoidable. 
* **Zero Development Exposure**: Under no circumstances shall development servers, Vite dev servers (`5173`), Webpack/Next.js dev ports (`3000`), or unauthenticated debug APIs (`8000`, `8080`) be exposed or deployed as production dependencies.
* **Fail-Closed Runtime**: Production client applications must never silently fall back to `localhost`, `127.0.0.1`, or unencrypted fallback endpoints. If a production endpoint is unavailable, the UI must display a clear, actionable degraded/offline state.

---

## 2. Production Environment Policy

KyvonOPS enforces strict tier separation across three environments:
1. **Development**: Local development using loopback interfaces, mock SQLite test databases in memory, and local mock SSH keys.
2. **Staging**: Edge test environment deployed on staging subdomains with strict TLS and test node inventories.
3. **Production**: Public distribution surface at `https://kyvonops.sys.thuyakyaw.com/` and authenticated operator workstation installations communicating via direct SSH and authenticated Cloudflare Tunnels.

### Zero Secrets in Source Invariant
Under no circumstances are cryptographic secrets, credentials, or private tokens committed to git history:
* **Strictly Prohibited in Source**: SSH passwords, SSH private keys, OS keychain items, database passwords, Cloudflare tokens, GitHub PATs, MCP API keys, session signing keys, JWT secrets, and TLS certificates.
* **Environment Files**: `.env`, `.env.production`, `.env.local`, `.env.development`, and `.env.test` are excluded via `.gitignore`. Only `.env.example` with non-secret placeholder variables is checked into source control.

## 5. HTTPS and Transport Security

* **Mandatory TLS 1.3 / 1.2**: All external HTTP traffic is redirected at the edge to HTTPS (301 Permanent Redirect). Unencrypted `http://` or insecure `ws://` connections are blocked.
* **HSTS Enforced**: Strict-Transport-Security header configured:
  ```http
  Strict-Transport-Security: max-age=63072000; includeSubDomains; preload
  ```
* **Cookie Security**:
  * `Secure`: Always required.
  * `HttpOnly`: Enforced on all session tokens to prevent DOM-based exfiltration.
  * `SameSite=Strict`: Prevents Cross-Site Request Forgery (CSRF).
* **Zero Secrets in URLs**: Authentication tokens, session keys, and query parameters must never be transmitted in URL search paths or query strings.

---

## 6. Cloudflare Edge Security & WAF

* **Edge Proxying**: All production DNS records are Orange-Cloud proxied through Cloudflare.
* **TLS Mode**: **Full (Strict)** with authenticated Cloudflare Origin CA certificates installed on the origin server.
* **Edge WAF Rules**:
  * OWASP Core Ruleset enabled at high sensitivity.
  * Bot Fight Mode enabled to eliminate automated credential stuffing.
  * Rate limiting applied on sensitive API and authentication endpoints.
* **Origin Obfuscation**: The real origin IP address is strictly shielded; direct traffic bypassing Cloudflare is rejected at the host firewall (`iptables` / `ufw` drops all traffic on port 80/443 not originating from Cloudflare IP ranges).

---

## 7. Origin Protection & Cloudflare Tunnel

* **Private Ingress via Tunnel**: Cloudflare Tunnel (`cloudflared`) creates outbound-only connections to Cloudflare edge nodes, allowing the origin host to completely close public inbound ports (`22`, `80`, `443`, `8080`).
* **Zero Public Management Exposure**: Host SSH (`22/tcp`), PostgreSQL/SQLite database files, Redis instances, and Docker daemon sockets (`/var/run/docker.sock`) are strictly inaccessible from the public internet.

---


## 9. CORS Policy

* **No Wildcards**: `Access-Control-Allow-Origin: *` is strictly prohibited on authenticated API endpoints.
* **Explicit Allowlist**:
  ```text
  Access-Control-Allow-Origin: https://kyvonops.sys.thuyakyaw.com
  Access-Control-Allow-Credentials: true
  Access-Control-Allow-Methods: GET, POST, PUT, DELETE, OPTIONS
  Access-Control-Allow-Headers: Content-Type, Authorization, X-Requested-With, X-Correlation-ID
  ```
* **Preflight Caching**: Preflight `OPTIONS` requests are cached for a maximum of 3600 seconds (`Access-Control-Max-Age: 3600`).

## 10. API Authentication Architecture

* **Cryptographic Session Tokens**: High-entropy tokens generated using cryptographically secure pseudorandom number generators (`ring::rand::SystemRandom` or Web Crypto API `crypto.getRandomValues()`). Predictable UUIDs, timestamps, or `Math.random()` are strictly forbidden.
* **Password Hashing**: Passwords stored on the server must use Argon2id with parameters `m=65536, t=3, p=4` or bcrypt with a minimum work factor of 12.
* **Session Lifecycle**: Explicit expiry (maximum 12 hours active, 30 minutes idle timeout), with server-side revocation capability across individual sessions or global tenant invalidation.

---

## 11. QR Device Pairing Security

When pairing companion mobile devices with the desktop control plane:
1. **Short-Lived Ephemeral Nonce**: The desktop generates a cryptographically random 256-bit nonce with a 60-second time-to-live (TTL).
2. **Zero Permanent Secrets in QR**: The QR code contains only `wss://kyvonops.sys.thuyakyaw.com/pair?nonce=<NONCE>&fp=<KEY_FINGERPRINT>`. It never encodes SSH keys or master credentials.
3. **Mutual Operator Confirmation**: Upon scanning, the desktop displays a visual confirmation prompt showing the mobile device fingerprint. Both devices must confirm within 30 seconds to complete pairing.
4. **Immediate Invalidation**: Nonces are strictly single-use and immediately invalidated in the Redis/memory store upon presentation.

---

## 12. Two-Factor Authentication (2FA / TOTP)

* **RFC 6238 Standard**: Time-based One-Time Passwords (TOTP) with HMAC-SHA1 or SHA256, 30-second step, 6-digit codes.
* **Recovery Codes**: Generated as 10 single-use 128-bit alphanumeric codes, hashed with Argon2id before storage in the database.
* **Brute-Force Lockout**: 5 consecutive failed TOTP attempts enforce a 15-minute exponential account backoff.

## 13. OS Credential Storage (Local-First Invariant)

KyvonOPS adheres strictly to local-first credential segregation:
* **Native Keychain Binding**:
  * **macOS**: Apple Keychain Services via `Security.framework` (`com.kyvon.ops`).
  * **Windows**: Windows Credential Manager (`wincred.h`).
  * **Linux**: FreeDesktop Secret Service API over D-Bus (`org.freedesktop.secrets`).
* **Zero Private Keys in SQLite**: The local SQLite database (`kyvon.db`) contains zero SSH passwords, private keys, or API tokens. It records only server aliases, IP addresses, ports, usernames, and public host-key fingerprints.
* **Fail-Safe Operation**: If the OS credential vault is locked or unavailable, the application prompts the operator for one-shot session credentials held only in ephemeral memory wrapped in `zeroize::ZeroizeOnDrop`.

---

## 14. SSH Transport & Host-Key Verification

* **Native SSH Implementation**: Powered by `russh` (pure Rust asynchronous SSH library).
* **Mandatory Host-Key Verification**: Implements `DesktopVerifier` checking against local `known_hosts`. Connections to unknown hosts prompt the operator with SHA-256 fingerprint validation. Changed host keys immediately abort the connection with a `HOST_KEY_MISMATCH` alert.
* **Bounded Output Buffers**: Remote command execution enforces strict limits:
  * Maximum execution timeout: 60 seconds (configurable).
  * Maximum stdout/stderr buffer: 2 MB per execution to prevent out-of-memory kernel panics.

---

## 15. Command Injection Defense & Safe Command Execution

* **Zero Unchecked Shell Interpolation**: Commands are constructed using typed structured argument vectors (`std::process::Command` / `russh` channel exec).
* **Service Management Hardening**: Systemd mutations (`start_service`, `stop_service`, `restart_service`) enforce strict alphanumeric service unit name validation (`^[a-zA-Z0-9_\-\.@]+$`).
* **Shell Command Redaction**: All commands executed on remote nodes pass through the [`kyvon_telemetry::scrub`](file:///Users/stephanfilip/cyberlab/kyvon_ops/crates/kyvon-telemetry/src/scrub.rs) regex engine before entering local state or audit logs.

## 17. MCP Zero-Secret Model

AI agents (**Codex Astra**, **Claude Opus**, and **Agy Gemini 3.8**) operate under a strict zero-secret capability model:
* **No Raw Credentials**: Private keys, database connection strings, passwords, and API tokens are never injected into the LLM prompt or tool call parameters.
* **Typed Capability Tools**: Agents receive opaque capabilities (`probe_host`, `get_telemetry`, `list_services`, `assess_service_action`).
* **No Arbitrary Shell Tool**: There is no generic `exec_command` or `run_shell` MCP tool exposed to AI agents.

---

## 18. AI Prompt Injection Defense

Server telemetry and log streams are treated as **untrusted user input**:
* **Untrusted Data Boundaries**: Remote log output, `/proc` process command lines, and environment variables are sanitized and escaped before display or LLM evaluation.
* **Instruction Segregation**: Log text and server output are encapsulated inside `<untrusted_system_data>` boundaries in LLM prompts with explicit instructions that system data cannot override policy directives.

---

## 19. API Key Security (BYOK)

* **No Frontend Storage**: User-provided API keys (OpenAI, Anthropic, Gemini) are never stored in browser `localStorage`, `sessionStorage`, or frontend React state.
* **OS Keychain Storage**: Keys are stored in the OS Keychain under service identifier `com.kyvon.ops.byok`.
* **Zero Logging**: Key values are matched against redaction regexes and stripped from all debug and error logs.

---

## 20. Database Security & Migrations

* **SQLite WAL Mode**: Local database utilizes Write-Ahead Logging (`PRAGMA journal_mode = WAL;`) and synchronous normal (`PRAGMA synchronous = NORMAL;`) for high concurrency and crash resilience.
* **Foreign Key Constraints**: `PRAGMA foreign_keys = ON;` strictly enforced.
* **Migration Immutability**: Schema migrations in `database/migrations/` are append-only. Existing applied migrations are never edited or rewritten.
* **Integrity Validation**: Startup routine executes `PRAGMA integrity_check(100);` before initializing application repositories.

---

## 21. Redis & Caching Security (If Deployed)

* **Network Isolation**: Redis binds exclusively to `127.0.0.1` or unix domain socket; never bound to `0.0.0.0`.
* **Authentication**: Enforces ACLs with high-entropy passwords (`requirepass` > 32 characters).
* **TLS Termination**: Any multi-node Redis cluster traffic enforces mTLS.

---

## 22. Container & Docker Security

* **Rootless Operation**: Remote agents run as unprivileged users.
* **No Public Docker Socket**: Docker daemon socket (`/var/run/docker.sock`) is never mounted into untrusted containers or exposed over TCP.
* **Capability Dropping**: Docker containers managed by KyvonOPS default to `--cap-drop=ALL` with explicit required capability additions (`CAP_NET_BIND_SERVICE`).

---

## 23. Tauri Desktop Security & IPC Boundary

* **Least Privilege Capabilities**: Tauri capabilities in `apps/desktop/src-tauri/capabilities/` restrict frontend IPC access to explicitly defined command sets.
* **No Broad Shell Access**: Tauri shell plugin execution is restricted; arbitrary command execution from the webview is completely disabled.
* **CSP Enforcement in Webview**:
  ```json
  "security": {
    "csp": "default-src 'self' asset: http: https: ws: wss:; img-src 'self' asset: https: data:"
  }
  ```

---

## 24. Frontend Security & DOM Injection Defense

* **Zero `dangerouslySetInnerHTML`**: All dynamic data, server logs, process tables, and markdown runbooks are rendered using React standard JSX escaping and sanitization pipelines (`DOMPurify`).
* **No `eval()` or Dynamic Code**: Dynamic script evaluation (`new Function()`, `eval()`, `document.write()`) is banned across the desktop frontend.

---

## 25. Rate Limiting & Abuse Prevention

* **Authentication Rate Limiting**: Maximum 5 failed login attempts per minute per IP before enforcing exponential backoff.
* **SSH Probe Throttling**: Connection attempts to individual host nodes are rate-limited to 3 concurrent connections per workstation to prevent target server firewall blocking (`fail2ban`).

---

## 26. Session & CSRF Protection

* **Origin Verification**: All state-mutating requests verify incoming `Origin` and `Referer` headers against the configured production host.
* **Anti-CSRF Tokens**: Double-submit cookie or synchronized cryptographic token pattern enforced on all state-changing POST/PUT/DELETE requests.

---

## 27. WebSocket Security (WSS)

* **Mandatory WSS**: Unencrypted `ws://` connections are refused.
* **Origin Validation**: WebSocket handshake verifies `Origin` header matches `https://kyvonops.sys.thuyakyaw.com`.
* **Message Framing & Size Caps**: Inbound WebSocket frames capped at 64 KB to mitigate DoS buffer exhaustion attacks.

---

## 28. WebRTC & Live Media Security (When Deployed)

* **DTLS-SRTP Encryption**: End-to-end media stream encryption enforced via DTLS 1.2+ and SRTP.
* **Ephemeral TURN Credentials**: TURN server credentials generated with time-limited HMAC authentication (TTL <= 10 minutes).

---

## 29. Voice & Audio Security

* **Zero Audio Key Exposure**: Third-party speech-to-text and text-to-speech API keys remain securely on the backend server or in the local OS Keychain; never sent to frontend webviews.
* **Explicit User Consent**: Microphone access requires active operator interaction and displays an un-dismissible recording indicator.

---

## 30. Structured Logging & Secret Redaction

* **Format**: Structured JSON / tracing subscriber with timestamps, log level, target module, and correlation IDs.
* **Redaction Engine**: The [`kyvon_telemetry::scrub`](file:///Users/stephanfilip/cyberlab/kyvon_ops/crates/kyvon-telemetry/src/scrub.rs) engine automatically strips:
  * OpenSSH / RSA / EC private keys (`-----BEGIN ... PRIVATE KEY-----`).
  * Bearer tokens, JWTs, and API keys (`Bearer [A-Za-z0-9_\-\.]+`).
  * Passwords and passphrase parameters (`password=...`, `passphrase=...`).

## 31. Tamper-Resistant Audit Ledger

* **Immutable SQLite Table**: Privileged actions record an audit event in the `audit_events` table within SQLite WAL:

* **Append-Only Invariant**: Audit records cannot be modified or deleted via UI or MCP commands.
