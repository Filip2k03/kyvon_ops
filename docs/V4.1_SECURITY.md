# KyvonOPS V4.1 Security

This document describes the **implemented** control gate, not a future hosted
identity product. Hosted MFA, session revocation, and a public API are not
verified and must not be advertised as available.

## Boundary

```text
Desktop UI · CLI · MCP · mobile companion (when built)
                 ↓
        typed intent (actor, target, action)
                 ↓
        risk classification (kyvon-security)
                 ↓
        operator confirmation for mutating writes
                 ↓
        OS keychain credentials (never in SQLite)
                 ↓
        russh session (host-key verification required)
                 ↓
        post-flight state check
                 ↓
        SQLite audit record (redacted)
```

There is no generic `exec_sh` MCP tool. Service start/stop is `systemctl` built
with `Cmd::new` plus quoted unit names. Process explorer has no kill button.

## What this worktree currently proves

- Policy, risk, redaction, and SSH host-key unit tests in the Rust workspace.
- Desktop service mutations call `assess_service_action` before `start_service` /
  `stop_service`.
- Telemetry collector is read-only POSIX `sh` piped over stdin; parsing is local.
- Public website does not invent GitHub release artifacts.
- `scripts/install.sh --desktop` refuses to install unless a GitHub release
  contains a matching AppImage **and** `SHA256SUMS`.
- Device pairing / hosted TOTP UI does not generate QR codes or ship a demo TOTP secret.
- Gemini and Cloudflare tokens are not written to `localStorage`.
- Cloudflare Pages `_headers` set HSTS, `frame-ancestors 'none'`, and no
  `Access-Control-Allow-Origin: *`.
- Tauri CSP no longer allows `'unsafe-eval'` or plaintext `http:`/`ws:` as defaults.

## Environments

| Name | Role |
| --- | --- |
| development | Local Vite/Tauri (`devUrl` on loopback). Not a public target. |
| staging | Optional; not independently verified in this pass. |
| production | Public static site at `https://kyvonops.sys.thuyakyaw.com/`. Operator SSH stays on the desktop. |

Required production values must fail closed. The website must not fall back to localhost APIs; there is no public KyvonOPS API in V4.1.

Secrets belong in OS keychain (desktop) or the host secret store (deploy). `.env.example` lists public frontend flags only. Never set `VITE_*` to a private API key.

## What remains LAUNCH BLOCKED

- Packaged, signed desktop installers and a published checksum manifest.
- Dependency audit (`cargo audit`) and a dedicated secret scanner in CI.
- Hosted authentication, MFA, recovery, CORS/CSRF for a public API (no API).
- Voice/WebRTC keys in the frontend (must stay absent).
- End-to-end MCP AppState control-gate proof on a live workstation.

If a real secret is found in git history, rotate it out of band; do not paste
values into issues or agent logs.
