# V4.1 client-only desktop behavior

KyvonOPS starts with an empty local installation. It does not seed companies,
servers, uptime, incidents, reports, or topology examples.

The normal flow is:

1. Open **My VPS**.
2. Choose **Connect a VPS**.
3. Enter the host, SSH port, user, and a supported authentication method.
4. Verify the SSH host fingerprint.
5. Run discovery and start telemetry.
6. Inspect the measured server in Command Center, Services, Docker, Logs, and
   Digital Twin.

The Digital Twin screen is derived from the selected local inventory record and
its completed host probe. Before discovery, it shows an explicit unavailable
state. It never substitutes sample nodes or plausible metrics.

The public desktop navigation does not expose the former client-workspace demo
or simulated mobile packaging screen. Unsupported operations remain labelled
unavailable rather than reporting simulated success.
