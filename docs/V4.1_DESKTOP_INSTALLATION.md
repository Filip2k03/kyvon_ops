# KyvonOPS V4.1 Desktop Installation

The desktop application is the recommended product for operators. Use a
published GitHub release only after checking its platform, architecture,
checksum, signature, and release notes. The current repository has no verified
published `v4.1.0` installer, so this guide does not provide a fake download URL.

The Tauri updater is disabled until signed metadata and a real public key are
configured. Do not treat a development build or an unsigned package as a
production update.

## macOS and Windows

1. Open the project’s GitHub Releases page.
2. Select a published installer that matches the operating system and CPU.
3. Download the checksum file and verify the artifact before opening it.
4. Install using the operating system installer and launch KyvonOPS.

Do not bypass an operating-system warning for an unsigned or mismatched file.
If the release does not contain a matching artifact, use the source workflow or
wait for a verified release.

## Linux

The supported source workflow is:

```sh
git clone https://github.com/Filip2k03/kyvon_ops.git
cd kyvon_ops
./scripts/install.sh --check
./scripts/install.sh --frontend
cd apps/desktop
bun run tauri build
```

The `--frontend` helper installs locked JS dependencies; it does not modify SSH
credentials or server data.

Linux binary install (fail-closed until a release exists):

```sh
# Download this file first, inspect it, then run it. Never: curl URL | sh
./scripts/install.sh --desktop
```

`--desktop` queries GitHub Releases over HTTPS, requires an AppImage whose name
matches the CPU architecture **and** a `SHA256SUMS` asset, verifies the digest,
then installs to `~/.local/bin/kyvon-ops`. Missing assets or a checksum mismatch
abort without installing.

## First run

Start with an empty local workspace. Connect only to infrastructure you own,
review the displayed SSH host fingerprint, and reject changed fingerprints until
the identity is verified out of band. Credentials belong in the OS credential
store where supported; they must never be pasted into public web forms or logged.

## Upgrade and removal

Read the release notes before upgrading. Preserve the local database and settings,
and keep a recoverable previous version until health checks pass. Never delete
the local workspace as part of an ordinary uninstall without an explicit backup
and data-removal decision.
