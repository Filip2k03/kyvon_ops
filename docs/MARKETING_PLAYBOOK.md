# Evidence-first developer launch playbook

The project is marketed through technical proof, not star requests.

## Core message

KyvonOPS is a local-first DevOps control plane for SSH, AI agents, MCP, and
policy-controlled operations. AI clients receive capabilities, not raw
infrastructure credentials.

## Content sequence

1. Publish a real, redacted desktop walkthrough.
2. Publish the installation and release evidence.
3. Explain one technical boundary (SSH host keys, MCP policy, or audit).
4. Ask for technical criticism from DevOps, Rust, and self-hosted communities.
5. Turn recurring feedback into a documented issue or discussion.

## Channel guidance

- LinkedIn: professional architecture and security lessons.
- X: short build logs with links to code and evidence.
- Reddit: one community-specific technical post; follow each community's rules.
- Hacker News: wait until a stable installable release and a useful technical write-up exist.
- Dev.to/Hashnode: publish implementation and failure reports, not slogans.

Never claim stable release, signed binaries, production readiness, user counts,
benchmarks, or integrations without repository evidence. Never automate stars,
forks, accounts, or engagement.
